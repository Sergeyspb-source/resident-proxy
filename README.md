# exitnode

Выход в интернет через компьютеры коллег. Клиент подключается к SOCKS5 на VPS1,
трафик идёт по цепочке VPS1 → VPS2 → ПК коллеги → сайт. Сайт видит домашний IP
коллеги, а не IP клиента и не IP серверов.

```
браузер
  │ SOCKS5 (только внутри VPN)
  ▼
VPS1   WireGuard + проброс порта       (кода нет)
  ▼
VPS2   relay: SOCKS5 + приём агентов   (этот бинарник)
  ▼ mTLS + yamux, агент сам звонит наружу
ПК коллеги   agent: туннель + панель + фильтры
  ▼
сайт
```

## Что видит кто

| Сторона | Видит | Не видит |
|---|---|---|
| Сайт | IP коллеги | клиента, VPS1, VPS2 |
| Коллега | IP VPS2 | IP клиента, VPS1 |
| VPS2 | IP коллеги и VPS1 | IP клиента, содержимое HTTPS |
| VPS1 | IP клиента и VPS2 | коллегу, содержимое HTTPS |

Волонтёру не нужен белый IP: агент сам открывает исходящее соединение к VPS2,
поэтому работает за NAT и CGNAT.

## Сборка

Windows-версия без чёрного окна консоли:

```
go build -ldflags "-H=windowsgui -s -w" -o bin/proxy.exe ./cmd/proxy
```

Логи пишутся в `agent.log` рядом с `proxy.exe`.

Для Linux-шлюза:

```
GOOS=linux GOARCH=amd64 go build -ldflags "-s -w" -o bin/exitnode ./cmd/proxy
```

## VPS2 — шлюз

Нужен TLS-сертификат на домен, который указывает на VPS2 (Let's Encrypt).

```
./exitnode relay \
  -socks 10.9.0.2:1080 \
  -tunnel :8443 \
  -cert /etc/letsencrypt/live/proxy.example.com/fullchain.pem \
  -key  /etc/letsencrypt/live/proxy.example.com/privkey.pem \
  -token "длинный-случайный-токен"
```

- `-socks 10.9.0.2:1080` — адрес в туннеле до VPS1, а не `0.0.0.0`. Так порт
  физически недоступен из интернета.
- `-tunnel :8443` — сюда подключаются агенты коллег.
- `-token` — общий секрет агентов, минимум 32 случайных символа. Он отвечает
  только за право узла подключиться к шлюзу; доступ клиентов — отдельно, ключами.

systemd:

```ini
[Unit]
Description=exitnode relay
After=network.target

[Service]
ExecStart=/opt/exitnode/exitnode relay -socks 10.9.0.2:1080 -tunnel :8443 \
  -cert /etc/letsencrypt/live/proxy.example.com/fullchain.pem \
  -key /etc/letsencrypt/live/proxy.example.com/privkey.pem \
  -token ВАШ_ТОКЕН
Restart=always
RestartSec=3
User=exitnode

[Install]
WantedBy=multi-user.target
```

## VPS1 — проброс без кода

Клиент ходит в VPN, поэтому SOCKS5 должен слушать только адрес в туннеле.

Через `socat` (проще всего):

```
socat TCP-LISTEN:1080,bind=10.8.0.1,fork,reuseaddr TCP:10.9.0.2:1080
```

Через nftables (быстрее, но нужен `ip_forward` и MASQUERADE):

```
sysctl -w net.ipv4.ip_forward=1
nft add rule ip nat prerouting ip daddr 10.8.0.1 tcp dport 1080 dnat to 10.9.0.2:1080
```

Порт 1080 на публичном интерфейсе VPS1 закрыть файрволом.

## ПК коллеги — агент

```
proxy.exe agent -relay proxy.example.com:8443 -token "длинный-случайный-токен" -name "Anna-Tallinn"
```

При запуске открывается окно-приложение (Edge или Chrome в режиме `--app`:
без адресной строки и вкладок) и иконка в трее. Закрытие окна ничего не
останавливает, полный выход — через меню иконки.

Что показывает панель:

- кнопка «Включить / Выключить»;
- активные подключения: куда, сколько времени, сколько байт;
- скорость в обе стороны и график за 60 секунд;
- сколько CPU и RAM ест именно программа и сколько — весь компьютер;
- ограничения: квоты, скорость, белый список доменов;
- ключи доступа для коллег;
- кнопка «Остановить все».

Полезные флаги:

| Флаг | Смысл |
|---|---|
| `-ports 80,443` | какие порты разрешены (по умолчанию 80 и 443) |
| `-max-sessions 8` | лимит одновременных подключений |
| `-quota-mb 0` | стартовая суточная квота трафика, МБ (0 = без лимита) |
| `-quota-month-mb 0` | стартовая месячная квота, МБ (0 = без лимита) |
| `-rate-kbps 0` | стартовый общий лимит скорости, КБ/с (0 = без лимита) |
| `-allow-domains ""` | стартовый белый список доменов |
| `-ui 127.0.0.1:17890` | адрес панели |
| `-tray` | не открывать окно при старте, только иконка в трее |
| `-server-name` | имя в сертификате, если оно отличается от адреса |
| `-insecure` | не проверять сертификат (только для теста) |

### Автозапуск

Галочка «Запускать при входе в Windows» в панели пишет запись в
`HKCU\Software\Microsoft\Windows\CurrentVersion\Run` с флагом `-tray`, то есть
после входа программа появляется только иконкой в трее. Галочка снимается там же.
Права администратора не нужны.

## Ключи доступа

Пока ключей нет, к узлу не может подключиться никто. Это сделано специально:
доступ выдаёт владелец компьютера, а не администратор шлюза.

Модель как в SSH, но проще:

1. В панели, блок «Доступ для коллег», впишите подпись (например, «Иван») и
   нажмите «Создать ключ».
2. Программа сгенерирует 32 случайных байта и покажет ключ строкой.
   На шлюз уходит только `sha256(ключ)`, сам ключ остаётся на вашем компьютере.
3. Передайте коллеге ключ и адрес шлюза любым личным каналом.
4. Коллега запускает клиент (см. ниже) и указывает этот ключ.
5. «Отозвать» удаляет ключ из панели и со шлюза; следующее подключение
   с этим ключом будет отклонено.

Ключ равносилен паролю: кто его получил, тот пользуется вашим выходом.
Смена ключа = создание нового и отзыв старого.

## Клиент — программа коллеги

Браузеры не умеют передавать логин и пароль в SOCKS5, поэтому коллега запускает
небольшой локальный клиент, который сам подставляет ключ:

```
proxy.exe client -server 10.8.0.1:1080 -key "КЛЮЧ_ОТ_ВЛАДЕЛЬЦА"
```

Он поднимает SOCKS5 на `127.0.0.1:1080` без пароля. Браузер настраивается на
этот адрес как на обычный локальный прокси. Всё, что проходит через него,
уходит на шлюз уже с ключом.

Проверка из терминала:

```
curl --socks5-hostname 127.0.0.1:1080 https://ifconfig.me/
```

Команда должна показать IP коллеги, а не ваш.

Для Chrome/Edge отдельный ярлык:

```
chrome.exe --proxy-server="socks5://127.0.0.1:1080" ^
  --force-webrtc-ip-handling-policy=disable_non_proxied_udp
```

Флаг WebRTC обязателен: без него браузер отдаёт реальный IP через STUN в обход
прокси. Это главная причина утечек, а не сам прокси.

## Ограничения узла

В панели есть блок «Ограничения узла». Он действует сразу, без перезапуска:

- **Квота в сутки** — при достижении активные подключения обрываются, новые
  отклоняются до следующего дня. `0` — без лимита.
- **Квота в месяц** — то же самое, но счётчик сбрасывается первого числа.
- **Скорость** — общий потолок на все подключения сразу, в КБ/с. `0` — без лимита.
- **Разрешённые домены** — белый список. `example.com` разрешает и все поддомены.
  Пусто — любые домены. IP можно указать точным адресом.

Настройки и израсходованный трафик хранятся в `agent-state.json` рядом с
`proxy.exe` и переживают перезапуск. Счётчики сбрасываются в полночь и первого
числа по местному времени. Флаги `-quota-mb`, `-quota-month-mb`, `-rate-kbps`,
`-allow-domains` задают стартовые значения, если файла настроек ещё нет.

## Защита

- Агент блокирует `127.0.0.0/8`, `10/8`, `172.16/12`, `192.168/16`,
  `169.254/16`, `100.64/10` и прочие служебные диапазоны. Клиент не попадёт
  в роутер или принтер коллеги.
- Домен резолвит агент и подключается уже к проверенному IP — это исключает
  DNS-rebinding.
- По умолчанию разрешены только порты 80 и 443.
- Клиент без действующего ключа не проходит авторизацию на шлюзе; отозванный
  ключ перестаёт работать сразу.
- Управляющие запросы панели требуют кастомный заголовок, поэтому сторонний
  сайт не сможет выключить узел через CSRF.
- Панель слушает только `127.0.0.1`.

## Чего пока нет

- UDP (звонки, игры) — только TCP.
- IPv6-адреса целей.
- Установщика и автообновлений.
- Оплаты, квот и учёта трафика по отдельным клиентам.
